# Sharing Implementation Plan

> **For executors:** execute with soltero-skills:lean-sdd. The Task Dependency
> Table below is the scheduling and review-depth contract.

**Goal:** A visitor can copy a link that carries their whole plan, open such a link as a
preview without losing their own plan, and download a picture of the floor plan and of the
3D view.

**Spec:** `docs/room-planner/specs/2026-11-17-sharing-design.md` (approved by the owner on
2026-11-17).

**Architecture:** The plan is encoded into the address's fragment by a new service,
`room-planner/services/shareLink.ts`, and read back only through `parsePlan`. The load hook
`usePlanPersistence` reads the fragment once, next to the saved plan, and either opens the
shared plan as the visitor's own or shows it as a preview (a new UI-store flag that stops
the autosave). The floor-plan picture is a pure canvas drawing; the 3D picture is captured
from whichever 3D view is mounted through a one-slot registry. A Share panel in the header
and a banner under the notice bar are the only new UI. Nothing new is stored and no request
is made.

**Tech stack / test runner:** Next.js 15, React 19, TypeScript, Zustand 5, Vitest + React
Testing Library + jsdom. One file: `npx vitest run <file>` from the repo root. Everything:
`npm run check` (typecheck, lint, tests, build). Repo root:
`/Users/franciscosoltero/Desktop/Code/Portfolio Website`. Branch: `sharing` (from `main` at
`e6c2a00`).

## Global Constraints

- Everything read from the address is untrusted. A shared plan reaches the stores only as
  the `doc` of a `parsePlan` success. No value from the link is used, shown or logged before
  that.
- Nothing is logged: no `console.*` call is added anywhere.
- No `innerHTML`, `dangerouslySetInnerHTML`, `eval` or `new Function`. Text reaches the page
  only as React text or canvas `fillText`.
- No network request is added (`fetch`, `XMLHttpRequest`, `sendBeacon`, image or script
  URLs). No new dependency.
- No change to `room-planner/domain/planSchema.ts`, `room-planner/services/browserPlanStore.ts`,
  `CONFIG.planStorageKey` or the saved format (version 3).
- Nothing under `room-planner/domain/` or `room-planner/view/` imports React, Zustand,
  three.js or anything under `room-planner/state/`.
- The fragment key is exactly `plan`: a share address ends `#plan=<data>`.
- User-facing strings are exact; every one is listed in the task that adds it.
- `/room-planner` First Load JS stays between 104 and 107 kB; the build output of
  `npm run check` prints it, and Task 7 quotes that line.
- Existing tests pass unchanged unless a task's "Test changes" line allows the change.
  Before finishing, each implementer greps the tests for every function, constant and
  string the task adds or changes and reports any pinned test outside its list.
- Tests first: in Tasks 1 to 5 the tests for the behavior table are written and seen to
  fail before the implementation, and the task report quotes the failing run.
- Rollback: one commit per task on branch `sharing`; the work reaches the live site only
  through a pull request the owner merges. Reverting the merge removes the feature. Opening
  or keeping a shared plan writes the visitor's saved plan, in the same storage key and the
  same format (version 3) the planner already writes, so a plan saved this way stays in
  place after a revert and the old code reads it; no flag and no migration are needed. A
  share link opened after a revert loads the visitor's own plan, since the old code ignores
  the fragment.
- Done means: every task's Verify passes, the final `npm run check` exits 0 with the First
  Load JS line in range, and live-check rows S1 to S18 are all recorded as passed. A failing
  live-check row is not a result to record and move on from (owner's decision, 2026-11-17):
  it gets a fix through the executor's fix loop, the fix is reviewed, and the affected rows
  are run again. Task 7 does not start while any row fails.
- Implementers stage only their own listed paths. Commits end with the trailer lines the
  dispatch gives. Never touch `Multiplayer_AI_Sprite.aseprite`.
- A dev server may be running on port 3478. Before `npm run check`, list the listener with
  `lsof -ti tcp:3478 -sTCP:LISTEN | xargs ps -o pid,comm -p`, read it, and stop only that
  process. Never stop a process by name, and never use `lsof -ti tcp:3478` without
  `-sTCP:LISTEN`.

## Task 1: Link codec

**Spec:** "The link"; "How it works", "Making the link" and "Reading the link".

**Files:**
- Create: `room-planner/services/shareLink.ts`
- Create: `room-planner/services/shareLink.test.ts`

**Interfaces — produces:**

```ts
export type ShareDecodeResult =
  | { status: 'ok'; doc: PlanDocument }
  | { status: 'invalid' }
  | { status: 'newer' };
/** The share data for a plan, or null when the plan cannot be shared. Never rejects. */
export function encodePlan(doc: PlanDocument): Promise<string | null>;
/** Reads share data. Never throws, never rejects. */
export function decodePlan(data: string): Promise<ShareDecodeResult>;
```

**Exact values:**
- Data is `<version>.<payload>`. Version `1`: the payload is base64url (no padding) of the
  raw-deflate (`'deflate-raw'`) of the UTF-8 JSON. Version `0`: base64url of the UTF-8 JSON,
  uncompressed.
- base64url alphabet: `A-Z a-z 0-9 - _`, no `=`. Golden vector: bytes `0xfb 0xff` encode
  to `-_8`.
- `MAX_BYTES = CONFIG.maxStoredChars` (524288): the most UTF-8 JSON bytes encoded or decoded.
- `MAX_DATA_CHARS = 2 + Math.ceil(MAX_BYTES * 4 / 3)` (699053): the longest data accepted.
- The JSON is `JSON.stringify` of an object built field by field from the six document
  fields in this order: `schemaVersion`, `units`, `room`, `items`, `openings`, `obstacles`.

**Behavior — `encodePlan`:**

| Case | Input / state | Expected |
|---|---|---|
| Normal, compression available | a valid plan | `'1.' + payload`; `decodePlan` of it gives `ok` with a doc deep-equal to `parsePlan(doc).doc` |
| No `CompressionStream` global | a valid plan | `'0.' + payload`; decodes to the same doc |
| Compression throws or its stream errors | a valid plan | falls back to `'0.'`; no rejection |
| Extra keys on the argument | a store state with actions | only the six fields are encoded |
| Plan `parsePlan` refuses | e.g. `units: 'yd'` | `null` |
| JSON over `MAX_BYTES` UTF-8 bytes | oversized plan | `null` |
| Non-Latin text | item named `寝室のベッド` and one with an emoji | round-trips exactly |
| Round trips (spec "Testing") | the starting plan (`createInitialDocument`); an L-shape room; a room with angled walls, a door, a window and a column; a plan with 40 items | each decodes to a doc deep-equal to `parsePlan(doc).doc` |

**Behavior — `decodePlan`:**

| Case | Input | Expected |
|---|---|---|
| Empty, or no `.` | `''`, `'abc'` | `invalid` |
| Longer than `MAX_DATA_CHARS` | 699054 characters | `invalid`, without decoding |
| Version not 1 to 3 digits | `'x.AAAA'`, `'.AAAA'`, `'1234.AAAA'` | `invalid` |
| Version 2 or higher | `'2.AAAA'`, `'17.AAAA'` | `newer` |
| Payload has a character outside the alphabet | `'0.ab+/'`, `'0.ab=='`, `'0.a b'` | `invalid` |
| Payload length is 1 more than a multiple of 4 | `'0.A'` | `invalid` |
| Empty payload | `'0.'`, `'1.'` | `invalid` |
| Version 0, bytes are not valid UTF-8 | `'0.' + b64url([0xff, 0xfe])` | `invalid` |
| Version 0, not JSON | `'0.' + b64url('hello')` | `invalid` |
| Version 0, JSON `parsePlan` refuses | `{}` | `invalid` |
| Version 0 or 1, plan with `schemaVersion: 99` | | `newer` |
| Version 0 or 1, a version 1 or 2 stored plan | an older saved format | `ok`, converted by `parsePlan` |
| Version 1, no `DecompressionStream` global | | `invalid` |
| Version 1, bytes are not a deflate stream | `'1.' + b64url('hello')` | `invalid` |
| Version 1, cut short | a valid link minus its last 10 characters | `invalid` |
| Version 1, inflates past `MAX_BYTES` | deflate of 600000 `'a'` bytes | `invalid`; reading stops once the total passes `MAX_BYTES` (the test checks no more than `MAX_BYTES` plus one chunk was read) |
| Key `__proto__` in the JSON | | never copied (already `parsePlan`'s rule); result has no polluted prototype |

**Notes:** jsdom may lack `CompressionStream`; the test file may start with
`// @vitest-environment node`. The "no global" rows remove the global for the test and
restore it after.

**Verify:** `npx vitest run room-planner/services/shareLink.test.ts` passes; `npx tsc --noEmit` clean.

**Commit:** `feat(room-planner): encode and decode a plan as share-link data`

**Behavior — load (the hook, once per store, where the saved plan is applied today):**

The hook reads `readShareData()` once, when it starts the load, and waits for both
`store.load()` and (when the data is not null) `decodePlan(data)` before applying anything.
"Own" is the `LoadResult` of `store.load()`.

| Share data | Own | Expected |
|---|---|---|
| null | any | exactly today's behavior; `decodePlan` not called |
| decodes `ok` | `loaded` | plan store reset to the shared doc; history cleared; `sharedPreview = { canKeep: true }`; nothing saved; fragment left in the address; own notice none |
| decodes `ok` | `empty` or `invalid` | plan store reset to the shared doc; history cleared; `store.save(sharedDoc)` called once; notice `SHARED_OPENED_NOTICE` (the storage notice instead when that save resolves false or rejects); `clearShareFragment()` called; `sharedPreview` stays null; the "saved plan could not be read" notice is not shown. (An unreadable saved plan is already removed by `browserPlanStore.load()` before it reports `invalid`, today and unchanged; nothing recoverable is overwritten here.) |
| decodes `ok` | `newer` | plan store reset to the shared doc; history cleared; `sharedPreview = { canKeep: false }`; `saveBlocked` not set yet; fragment left |
| decodes `ok` | `unavailable` | as the row above, and the storage notice is shown |
| decodes `invalid` | any | own applied exactly as today; then notice `SHARED_INVALID_NOTICE` (it replaces a notice the own load set); `clearShareFragment()` called |
| decodes `newer` | any | as the row above with `SHARED_NEWER_NOTICE` |
| `decodePlan` rejects (it must not) | any | treated as `invalid` |
| StrictMode second effect run / same store again | | the share data is not read or applied a second time (same guard as the saved plan) |

**Behavior — while `sharedPreview` is not null:**

| Case | Expected |
|---|---|
| A document change | no `store.save` call, however long the wait; also none on `pagehide`, hidden `visibilitychange` or unmount |
| Undo, redo, edits | work as usual (no change to the history store) |
| A `hashchange` event when `readShareData()` is not null (any time the hook is mounted, preview or not; added to the spec with the owner's approval on 2026-11-17) | `reloadPage()` called once; listener removed on unmount |
| A `hashchange` event when `readShareData()` is null | nothing |

**Behavior — `keepSharedPlan(store)`:**

| Case | Expected |
|---|---|
| `sharedPreview` null, or `canKeep` false | does nothing |
| Save resolves true | `store.save(currentDocument())` called once (the plan as it is now, edits made while previewing included); then `sharedPreview = null`, `clearShareFragment()`, history cleared; later document changes autosave again |
| Save resolves false or rejects | storage notice set; `sharedPreview` unchanged; fragment unchanged |
| Called twice before the first settles | one save |

**Behavior — `leaveSharedPlan(store)`:**

| Case | Expected |
|---|---|
| `sharedPreview` null | does nothing |
| Otherwise | `store.load()` called (a rejection counts as `unavailable`); `sharedPreview = null`; the result applied exactly as a normal load applies it (`loaded` → that plan; `empty` → seeded plan; `invalid` → seeded + its notice; `newer` → seeded + `saveBlocked` + its notice; `unavailable` → seeded + storage notice); history cleared; `clearShareFragment()` |
| Called twice before the first settles | one load |

  obstacle fill `#c5cad3`, stroke `#3d4a63`; conflict fill `#fbdada`, stroke and label

- Line widths: walls 10 (`lineJoin 'miter'`); furniture and obstacles 3; door or window gap
  10 in `#ffffff`; window line 4; door leaf 3; door arc 2.
- Fonts: names `500 26px Barlow, sans-serif`; wall lengths `600 28px Barlow, sans-serif`;
  credit `400 22px Barlow, sans-serif`.

| 2. Floor | the outline, closed, filled with the floor colour |
