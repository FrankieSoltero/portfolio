## Defects found

1. **B15: a migrated version 1 plan stays in storage as version 1 until the first change.**
   Reproduce:
   1. Run `npm run build && npx next start -p 3210` and open `http://localhost:3210/room-planner`.
   2. In the console, set the old plan: `localStorage.setItem('room-planner:plan:v1', JSON.stringify(<v1 seeded document from git show 6ed5e96:room-planner/domain/catalog.ts>))`, then reload.
   3. Wait at least 500 ms. `JSON.parse(localStorage.getItem('room-planner:plan:v1'))` still has `schemaVersion: 1` and the bed at `x: 40, y: 0, rot: 0`.

   The plan on screen is migrated correctly (bed centre (72, 42.5), desk (131, 131.5) at 90°). The key is rewritten as version 2 only after the first document change. This follows the documented rule in `room-planner/hooks/usePlanPersistence.ts` ("The document applied from the load is not saved back"). Fixing it means either saving after a migrating load, or changing the row to read the stored values after a first change. Both are design calls, so this is left to the controller. No code was changed.

2. **B18: the whole-session network log includes Google Fonts requests from the portfolio home page.**
   Reproduce: in the same session, open `http://localhost:3210/` and watch the network log. There are 6 requests to `fonts.googleapis.com` / `fonts.gstatic.com`, made by `public/index.html` lines 14 to 16 (Press Start 2P, Pixelify Sans, VT323). This is the portfolio's existing behaviour, not the planner's. `/room-planner` and `/papers` request only `localhost:3210`, and no request carries `schemaVersion`. Fixing it needs either self-hosted fonts on the home page (`public/**`, outside this plan, which the Global Constraints forbid editing) or a row that is scoped to `/room-planner`. Left to the controller.
