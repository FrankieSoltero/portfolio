# Drills: mistakes and fixes

A running log of what went wrong while building the drills section and the rule that
prevents a repeat. Newest entries go at the bottom.

| Date | Area | Mistake | Fix or rule |
|------|------|---------|-------------|
| 2026-11-20 | Fairness gate | vitest 5's `fsModuleCache` made the solution run reuse the starter's transform, so the gate tested the starter twice and could never fail on a broken solution. | Fixed with `fsModuleCache: false` in `vitest.drills.config.mts`. Rule: prove a two-variant gate can fail by running it against a deliberately broken solution. |
| 2026-11-20 | Git | The feature branch was first cut from another session's branch in a shared checkout and picked up two foreign commits. | Rebuilt on `main` in a separate git worktree. Rule: run `git branch --show-current` immediately before branching, and give parallel work its own worktree. |
| 2026-11-20 | Plan | The plan gave no task ownership of the CSS for the index and drill pages. | A styling task (Task 19) was added. Rule: every user-visible surface in a plan needs a task that owns its stylesheet. |
| 2026-11-20 | Check tables | The plan marked a `comment-threads` check and a `posts-feed` check red, but one planted bug was not independently catchable and one row passed on the starter. | One assertion was added to each check (`Threads loaded: 2`; the `Could not load comments` alert before the retry). Rule: for every planted bug, plant it alone in the solution and require a red check, and trace every row on the starter before fixing the table. |
| 2026-11-20 | Fairness gate | The gate does not compare the starter's failing checks with the plan's table, so a stub starter passes. | Rule until the gate is tightened: reviewers trace each row by hand. |
| 2026-11-20 | Implementer hygiene | A scratch cleanup ran `rm -rf content` and removed a tracked folder; it was restored with `git checkout`. | Rule: delete only exact scratch paths you created, never a parent folder. |
| 2026-11-20 | Tooling | `tsc` failed with TS18003 when `tsconfig.drills.json` matched no starter files. | Added `"files": []` to `tsconfig.drills.json` so `tsc` passes with zero starter files. Rule: a tsconfig whose `include` glob can match zero files needs `"files": []`, and any new typecheck step must be run once against an empty input set before it is added to `npm run check`. |
| 2026-11-20 | Lint | `drills/useProgress.ts` needed one `eslint-disable-next-line react-hooks/set-state-in-effect`, the first suppression in the repo. | Accepted: the hook must render empty first and load stored progress after mount. Do not copy the suppression elsewhere without the same reason. |
| 2026-11-23 | Progress store | `useProgress` kept its own copy of progress in every component. With the workspace on the drill page, one component records "solution revealed" and another records "completed"; the second write would have come from a stale copy and dropped the reveal, so "done with help" would have been lost. Found while planning, before the workspace was added. | Fixed in `8e6ad38` (`fix(drills): one shared progress store for every component on the page`): every hook on the page shares one store, each change is applied to what storage holds at that moment, and other tabs are followed through the `storage` event. Rule: data kept under one storage key has one owner on the page; components never write it from their own copies. |
| 2026-11-23 | Built-page check | The check removed `<script>` elements after decoding HTML entities. Visible text such as `&lt;script&gt;` then looked like a real tag, and the removal swallowed the visible markup up to the next real `</script>`, so a check name leaking into that markup would have passed. The risk was noticed in the task report but filed as minor; the task review sent it back. | Fixed in `9977023` (`fix(drills): strip script elements from built pages before unescaping`): scripts are removed from the raw file, then entities are decoded. On a deliberately tampered built page the old script printed `drills pages: 11 OK` and the fixed one failed. Rule: structural HTML parsing (removing elements, matching tags) runs on the raw markup; decoding entities is the last step, applied only to the text being compared. A risk you notice in your own work gets fixed, not filed. |
| 2026-11-23 | Draft store | zod 4's `z.record` skips a `__proto__` key without validating its value, so a stored draft with `"__proto__": 5` among its files passed validation, against the rule that one bad value discards the whole draft. | `parseDraft` checks every own value of `files` again (`everyFileValid` in `drills/draft.ts`) and builds its result with `Object.create(null)`; three tests cover a non-string, an object and a too-long value under `__proto__`. Rule: a zod record does not validate `__proto__`; re-check the own values of untrusted JSON objects. |
| 2026-11-23 | Dependencies | Drillbox declares `vitest` as an optional peer dependency, so installing Drillbox put the vitest, vite and jsdom packages under a production dependency: 88 entries in `package-lock.json` lost `"dev": true` (55 of them became `"devOptional": true`), and `npm ci --omit=dev` now installs them. | Not fixed here: the fix belongs in Drillbox (drop the peer, or ship the vitest shim separately). Check how the host installs packages before the first deploy. Rule: after adding a dependency, compare the lockfile's `dev` and `optional` flags, not only the versions. |
| 2026-11-23 | Build | The frame page is written by `npm run frame`, which runs as the `prebuild` script. A host that runs `next build` directly skips it and would ship no frame page, and nothing failed. | The built-page check now fails with `frame page missing; run npm run frame` when `public/drillbox/frame.html` is missing or empty. That check runs in `npm run check`, not on the host, so the first deploy log must also be checked for the `drill frame:` line. Rule: a build step that lives in an npm `pre` script needs a check that fails when its output is missing. |
| 2026-11-23 | Lint | The first `WorkspaceHost` read the draft synchronously inside an effect and silenced `react-hooks/set-state-in-effect` with a new `eslint-disable` comment, breaking the rule of no new suppressions. | The suppression was removed: the draft is read in a promise callback after mount, with a cleanup flag, and the host renders nothing until the draft for the current drill has arrived. Rule: check the lint rules before reaching for "read storage in an effect"; the one existing suppression is not a pattern to copy. |
| 2026-11-23 | Unit tests | In vitest, a bare `next/dynamic` import resolves to the Pages Router version, which hands load errors to the `loading` component instead of throwing them to the error boundary, so the load-failure test never saw the alert. | The tests mock `next/dynamic` with `next/dist/api/app-dynamic`, the version Next uses for app code. Rule: unit tests of App Router client code use the implementations Next aliases in for the app. |
| 2026-11-23 | Browser tests | The "Clean console" test failed in WebKit with five `Failed to fetch RSC payload … Load failed` errors. The test left `/drills` while Next.js was still prefetching the drill links in view, and the page being left logged the aborted fetches. It was a test timing problem, not a site defect. | The test waits for `/drills` to finish loading (`networkidle`) before it opens a drill; the expectation is unchanged. Rule: when collecting console errors across navigations in a Next.js app, let each page finish its link prefetches first. |
| 2026-11-23 | Screenshots | The first full-page screenshot at 1280 wide showed a blank preview frame, because Chromium leaves a sandboxed frame below the fold blank in a full-page capture. CodeMirror's line numbers were also squashed (14 px rows against 23.8 px code lines), because CodeMirror does not measure an editor until it is in view. | The screenshot helper stretches the viewport to the page's height (and asserts the page height is unchanged), then waits until the gutter rows match the code lines. Rule: a full-page capture of a frame or a lazily measured editor needs that element in view first. |
| 2026-11-23 | Tests | The Script test compared the 1.18 MB generated frame page with `toBe`, and a failure printed a 136 KB diff of minified code. | The test compares SHA-256 hashes of the two strings. Rule: assert on a fingerprint of a large generated file, not on the raw text. |
| 2026-11-23 | Plan | The plan themed the workspace but never checked the page column against the approved mockup. Drill pages kept the section's 704 px (44rem) reading column, so at 1280 wide the editor and preview stacked and the badges dropped under the title, where the mockup has them side by side. Task 9's screenshots showed it. | A plan amendment (Task 12) widened drill pages only (`.drills:has(.drills-drill)`: `max-width: 1160px`, 24 px side padding), kept prose at 760 px and left the index at 704 px. Rule: when a plan cites an approved mockup, one task compares the page layout with it (column width, what sits beside what), not only the colours and type. |
| 2026-11-23 | Visual review | The review file first gave the mockup's workspace row as 1112 px. The mockup sets `max-width: 1160px` without `box-sizing: border-box`, so its content is 1160 px; this page's border-box column, also written `max-width: 1160px`, gave 1112 px. | Measured in Chromium and corrected; the page column was then fixed to match the mockup (`c2bc735`, below), so no width difference remains. Rule: in a page without a box-sizing reset, `max-width` excludes padding; measure the mockup instead of reading its CSS. |
| 2026-11-23 | Rulings | The plan asked for the check list to have "no left padding from the site's `ol` rule", and a ruling during the task restated it as "check list padding-left 0px". The list is a `ul`, the carried-over Drillbox override gives it `padding: 8px 16px`, and the ruling did not say whether it meant the list or its rows. | The implementer asserted that the `ul` keeps 16 px (not the site's 22.4 px) and each row has 0 px, flagged the reading, and the task review passed with it. Rule: a ruling on a computed style names the element and says whether it overrides a rule carried over on purpose. |
| 2026-11-23 | Layout | Task 12's brief copied the mockup's `max-width: 1160px` onto this page's column. The mockup's box is content-box, this column is `box-sizing: border-box`, so the 24 px side padding came out of the 1160 px and the content row was 1112 px, 48 px narrower than the mockup's. | `c2bc735` writes `max-width: 1208px` (1160 px of content plus the padding), and the theme browser test checks that value and the editor and preview widths against the mockup's at 1280 wide. Rule: when copying a width from a design, check which box it measures (content box or border box) in the design and in the page. |
| 2026-11-23 | Tests | The stand-in `Workspace` in `WorkspaceHost.test.tsx` and `DrillWorkspace.test.tsx` recorded each mount in a passive `useEffect`. The component sets state in a promise callback outside `act`, so React could commit the DOM and run that effect in a later task: `findByTestId` saw the workspace and the test read the mount list before the effect had run. The final review saw it fail once in a full `npm run check`; it failed again once in 100 runs of the two files under CPU load. | The stand-ins record in `useLayoutEffect`, which runs inside the commit; 200 runs under the same load then passed. Rule: a test double that records in `useEffect` can be observed after the DOM it belongs to; record in `useLayoutEffect`, or assert the record through `waitFor`. |
| 2026-11-23 | Workspace | Between the `WorkspaceHost` import resolving and the draft being read, the host rendered nothing, so the workspace section was empty for a moment. And `RETRY` removes itself when pressed, so keyboard focus fell to `<body>`. | `DrillWorkspace` passes the fallback to `WorkspaceHost` as a prop (not through its context, which would make the lazily loaded module import the module that loads it), and the host shows it until the draft is read. After a retry the section gets `tabindex="-1"` and the focus. Rule: every step of a loading chain (import, then data) shows the placeholder; a control that removes itself hands the focus on. |
| 2026-11-26 | Deploy | The first production build of the drills merge (`9d6b69e`) failed on Vercel after 28 s: `TypeError: Cannot read properties of null (reading '1')` in `next/font/google`'s loader, which downloads font CSS from Google while building. The preview build of the same tree had passed a minute earlier, so the code was not the cause. Production kept serving the previous deployment. | Built again by merging this note. Rule: a pull request's green preview does not prove the production build; after a merge, wait for the production status and open the live pages. `/papers` and `/drills` both depend on a build-time download from Google Fonts; self-hosting them with `next/font/local` would remove that dependency. |
